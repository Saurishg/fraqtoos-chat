Video Animation
🎬
Wan2.1 Text → Video
Generate a 5-second 832×480 clip from any text prompt using Wan2.1-T2V-1.3B. Runs fully local on GPU.
/video <prompt>
🖼➡🎬
Wan2.1 Image → Video
Attach any photo, then describe the motion. Wan2.1-I2V-14B animates it into a video. First run downloads ~28 GB model.
📎 attach → /animate <motion>
🕺
MimicMotion
Attach avatar image (🪄 mode) + driving video. SVD-XT transfers the motion onto the avatar.
🎬 button → 🪄 Avatar
🕺
AnimateAnyone
Pose-driven animation with AnimateAnyone pipeline. Toggle video chip to 🕺.
🥋
CHAMP
Full-body SMPL motion transfer. Toggle video chip to 🥋 CHAMP.
💃
Wan2.2-Animate (NEW)
Attach a character image (🪄 Avatar mode) + a driving video, then cycle the video chip to 💃 Wan2.2-Animate. The 14B model (Q8 GGUF) replicates the body motion and facial expression onto your character. Runs on the AMD 6800 XT via ROCm (ComfyUI :8189), accelerated by the LightX2V 8-step distill LoRA. ~3–8 min/clip.
🎬 + 🪄 → 💃 Wan2.2-Animate
🎛️
VACE Control (NEW — best for motion control)
Wan2.1-VACE-14B (Q8 GGUF) — structure/motion-controlled video generation. Attach a control video (its motion/structure guides the output) + a reference image (the look), cycle the video chip to 🎛️ VACE Control, and add a text prompt. Also handles depth/pose/edge control videos. Runs on the 6800 XT (ComfyUI :8189), accelerated by the LightX2V 8-step distill LoRA. ~2–7 min/clip.
🎬 + 🪄 → 🎛️ VACE Control

Accessibility
⌨
Visible Focus Ring
Every interactive element shows a clear amber outline when focused via Tab, so keyboard users always know where they are.
🔉
Screen-Reader Friendly
Chat region announces streamed replies via aria-live; every icon button has an aria-label; modals use role="dialog".

Reduced-Motion Mode
Honors the OS setting prefers-reduced-motion: reduce — fade-in, smooth scroll, and typing-dot bounce are disabled for users who need still UIs.

WCAG Contrast
Secondary text colors were lifted to clear WCAG AA on the dark background — no more washed-out timestamps and helper text.
Server Automation
⚙️
/exec — AI Agent Shell
Type /exec <task> to run the local gemma-agent on the server. It has bash, file read/write, and web search tools. Smart-routed to the best local model. Streams live elapsed time while working. Examples: restart services, check logs, edit configs, run scripts.
/exec check disk space
🌿
Chia AI Watcher (every 2h)
phi4 reads new Chia debug.log lines every 2 hours and classifies them as ok / warning / critical. If a fix is possible, the gemma-agent executes it automatically (service restarts, WAL checkpoint, cache flush). WhatsApp alert sent on critical issues, max once per 4h.
auto-fixes via agent
🌾
Chia Health Monitor (08:00 daily)
Rule-based daily Chia farming summary sent via WhatsApp at 08:00. Checks: farming status, hours since last block won vs expected, prover error count (Gigahorse giga37 bug), block validation spikes, coin store write slowness, and pooling errors.
/exec run chia_health
📋
AI Fix Log
Every auto-fix the Chia AI Watcher applies is logged with timestamp, command run, and agent result. Read it with /exec cat /home/work/fraqtoos/logs/chia_ai_fixes.log.
/exec cat chia_ai_fixes.log
📡
Orchestrator Bots
FraqtoOS runs: Portfolio Bot (06:00), morning AI analysis (07:00), Chia health (08:00), Utility Bill Bot (10:00), watchdog full (12:00), BTC Strategy Bot (22:00), daily digest (23:00), Chia AI Watcher (every 2h), watchdog (every 30m).
/bots to see live state
🔧
Safe Auto-Fix Allowlist
The Chia AI Watcher only executes commands from a verified allowlist: chia CLI, systemctl, sqlite3, python3, df, du, sync. No rm, mv, or destructive operations are ever auto-run — the agent will refuse them.
